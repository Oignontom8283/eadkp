Le RGB 565 ​

Le format RGB 565 est un format de couleur sur 16 bits, utilisé principalement dans les systèmes embarqués et les écrans à mémoire limitée. Cette page explique son fonctionnement, ses avantages et comment convertir depuis et vers le RGB 888.

Différenciation ​

Lorsqu'on parle de RGB, sans précision, on fait généralement référence au format RGB 888. Mais alors, qu'est-ce que le RGB 888 ?

Le RGB 888, c'est le fameux format de couleur où l'on représente la couleur grâce au Rouge, Vert et Bleu, chacun quantifié de 0 à 255.

Exemple avec du CSS :

css
background-color: rgb(255, 0, 0); /* Rouge */
background-color: rgb(0, 255, 0); /* Vert */
background-color: rgb(0, 0, 255); /* Bleu */
background-color: rgb(255, 255, 0); /* Jaune */
background-color: rgb(0, 255, 255); /* Cyan */
background-color: rgb(255, 0, 255); /* Magenta */
background-color: rgb(255, 255, 255); /* Blanc */
background-color: rgb(0, 0, 0); /* Noir */
etc...

Le RGB normal (donc le RGB 888) a donc un total de 256 x 256 x 256 = 16 777 216 couleurs possibles.

Pourquoi le 888 ? ​

Le RGB 888 signifie que chacune des trois couleurs (Rouge, Vert, Bleu) est encodée en binaire sur 8 bits (1 octet), soit 2^8 = 256 valeurs possibles (de 0 à 255).

Chaque couleur utilise donc 8 bits, d'où le nom RGB 888 (8 bits pour le Rouge, 8 bits pour le Vert, 8 bits pour le Bleu). Ce qui fait un total de 8 + 8 + 8 = 24 bits par pixel, soit 3 octets par pixel.

RGB 565 ​

Comme on l'a vu, le RGB 888 utilise 8 bits par couleur. Le RGB 565, c'est le même principe, mais avec une répartition différente des bits.

En premier lieu, 5 bits pour encoder le Rouge en binaire, 6 bits pour le Vert, et 5 bits pour le Bleu. On a donc 2^5 = 32 valeurs possibles pour le Rouge et le Bleu, et 2^6 = 64 valeurs possibles pour le Vert. Soit un total de 32 x 64 x 32 = 65 536 couleurs possibles.

Avantages et inconvénients ​

Vous allez me dire : "Mais 65 536 couleurs, c'est rien du tout comparé aux 16 millions de couleurs du RGB 888 !". Et OUI, c'est vrai, mais pour beaucoup de cas d'utilisation, avoir moins de profondeur de couleur est acceptable, surtout quand on compare avec l'énorme avantage du RGB 565. Vous allez comprendre.

Le RGB 565 utilise donc 5 bits + 6 bits + 5 bits = 16 bits par pixel, soit 2 octets par pixel. Le RGB 888, lui, utilise 24 bits par pixel, soit 3 octets par pixel.

UN octet de différence par pixel ! Alors oui, pour des ordinateurs avec 8, 16, 32 Go de RAM, 1 octet de plus ou de moins, c'est rien. Mais sur des systèmes embarqués, qui ont 256 Mo, 512 Mo, ou même 256 Ko de RAM (comme dans notre cas, avec la Numworks), chaque octet compte !

Faisons un petit calcul rapide :

bat
La calculatrice Numworks a un écran de 320x240 pixels.
320 x 240 = 76 800 pixels
En RGB 888 : 76 800 pixels x 3 octets = 230 400 octets (~225 Ko)
En RGB 565 : 76 800 pixels x 2 octets = 153 600 octets (~150 Ko)

Soit une différence de 76 800 octets (~75 Ko).
Ce qui correspond à environ 30% de RAM en moins utilisée !

Mais le principe reste le même : moins on utilise de mémoire, mieux c'est. Et puis, cela rend aussi les écrans moins chers !

Pourquoi 5, 6, 5 bits ? ​

Pourquoi pas 555 ou 666 bits alors ?

Vous l'aurez remarqué, 5 + 6 + 5 = 16 bits, ce qui fait un total rond et compact de 2 octets par pixel. Et c'est bien plus pratique de stocker des choses sur des octets entiers. Sinon il faudrait faire du bit-packing, et c'est plus compliqué à gérer et plus de calculs à faire.

Donc pourquoi c'est le vert qui a 6 bits et pas le rouge ou le bleu ? Car l'œil humain est plus sensible au vert qu'aux autres couleurs. Donc vu qu'on a moins de profondeur de couleur, on privilégie la couleur la plus importante pour l'œil humain. Ça permet d'avoir un meilleur rendu visuel, déjà qu'on a moins de couleurs, autant les rendre moins ternes que possible !

Conversion ​

RGB 888 -> RGB 565 ​

Pour convertir une couleur du format RGB 888 au format RGB 565, c'est assez simple. Il suffit de réduire les 8 bits en 5 ou 6 bits selon la couleur. On va devoir couper les bits de poids faible (les bits les moins significatifs (à droite)), en gros, on retire de la précision.

Exemple en Rust :

rs
fn rgb888_to_rgb565(r: u8, g: u8, b: u8) -> u16 {
    let r5 = (r >> 3) as u16; // Prendre les 5 bits de poids fort du rouge
    let g6 = (g >> 2) as u16; // Prendre les 6 bits de poids fort du vert
    let b5 = (b >> 3) as u16; // Prendre les 5 bits de poids fort du bleu

    (r5 << 11) | (g6 << 5) | b5 // Combiner les bits dans un seul entier u16
}
// rgb888_to_rgb565(66, 138, 245) => 0b01000_100010_11110 = 0x442E

RGB 565 -> RGB 888 ​

On est sur le principe inverse. On va devoir étendre les 5 ou 6 bits en 8 bits. On rajoute des bits de poids faible (les bits les moins significatifs (à droite)). En gros, des zéros.

Exemple en Rust :

rs
fn rgb565_to_rgb888(rgb565: u16) -> (u8, u8, u8) {
    let r5 = (rgb565 >> 11) & 0x1F; // Extraire les 5 bits du rouge
    let g6 = (rgb565 >> 5) & 0x3F;  // Extraire les 6 bits du vert
    let b5 = rgb565 & 0x1F;         // Extraire les 5 bits du bleu

    let r8 = (r5 << 3) | (r5 >> 2); // Étendre à 8 bits
    let g8 = (g6 << 2) | (g6 >> 4); // Étendre à 8 bits
    let b8 = (b5 << 3) | (b5 >> 2); // Étendre à 8 bits

    (r8 as u8, g8 as u8, b8 as u8)
}

def rgb565_to_rgb888(rgb565):
    r5 = (rgb565 >> 11) & 0x1F  # Extraire les 5 bits du rouge
    g6 = (rgb565 >> 5) & 0x3F   # Extraire les 6 bits du vert
    b5 = rgb565 & 0x1F          # Extraire les 5 bits du bleu

    r8 = (r5 << 3) | (r5 >> 2)  # Étendre à 8 bits
    g8 = (g6 << 2) | (g6 >> 4)  # Étendre à 8 bits
    b8 = (b5 << 3) | (b5 >> 2)  # Étendre à 8 bits

    return (r8, g8, b8)

TL;DR ​

  • RGB 888 : 24 bits par pixel (3 octets), un octet par couleur, 16 millions de couleurs.
  • RGB 565 : 16 bits par pixel (2 octets), 5 bits pour le rouge, 6 bits pour le vert, 5 bits pour le bleu, 65 mille couleurs.
  • Idéal pour les systèmes embarqués avec peu de mémoire, comme la calculatrice Numworks.

Conversion :

  • RGB 888 -> 565 : Décaler les bits de poids faible (droite) et combiner sur un u16.
  • RGB 565 -> 888 : Extraire les bits et étendre en ajoutant des bits de poids faible (droite).
